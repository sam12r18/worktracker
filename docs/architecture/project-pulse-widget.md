# Project Pulse Widget

The Windows Agent exposes a compact, always-on-top side widget intended to remain visible while the main WorkTracker window is hidden.

## Data shown

- four most recent/active Pulse items (classified Projects plus an active phone-call timer when present);
- today's credited time per Project;
- direct vs Continuity Bridge time;
- current/latest application;
- active/recent state;
- global Effort, Coverage and Concurrent totals.

The active raw foreground segment is represented by an in-memory provisional `ActivitySession` generated by `TrackingEngine.CreateProvisionalSession`. Active manual timers use the same provisional-only presentation principle through `ManualTimerService.CreateProvisionalSessions`. Provisional records are never persisted or synced. When a real raw/manual session is finalized, the provisional record disappears and the persisted session takes its place.

This keeps the widget live while preserving SQLite/API raw-session semantics.

## UX

- shown by default on startup;
- can be hidden with `×`;
- can be restored from the main-window `ویجت فعالیت` button or System Tray;
- docks near the right edge on first show;
- remains topmost and can be dragged/resized.

## Compact mode

The widget can toggle between full and compact layouts without losing the four recent/active counters. Compact mode remains a narrow side widget and grows just enough to show four rows plus the quick-call controls and shows:

- active/recent indicator;
- Project name;
- live credited duration;
- one-line Effort + Concurrent summary.

Returning to full mode restores the previous resizable width/height kept for the current process.


## Quick phone-call timer

Project Pulse exposes a small `☎` action for parallel phone-call tracking. The action is intentionally project-scoped:

- the target is the Project of the current green/live foreground classification;
- if no classified live Project exists, the call action is disabled and does not invent a Project assignment;
- only one quick phone call can be active at a time;
- `■` ends the call; the resulting record is persisted as a normal `manual_timer` Activity Session and queued through the normal Sync outbox;
- auto foreground capture continues while the call is active, so call time is additive and may overlap the same or another activity exactly like other manual timers;
- the active call is shown as its own `☎ Project` Pulse row while the Project total continues to show total credited Project effort; this is a presentation detail, not duplicate accounting;
- active manual timers are represented by in-memory provisional sessions in Pulse so their counters and global Effort update every second; only the finalized timer is persisted.

If an active Activity Type has code `call-meeting` (preferred for this WorkTracker deployment), or another conventional phone-call code (`phone_call`, `call`, `phone`, etc.), or a name containing `تماس`/`phone`/`call`, the Agent assigns it to the quick call. Otherwise the call is still stored safely with no Activity Type and can be classified later.
