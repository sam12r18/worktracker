## Capture pipeline

1. Observe the current foreground HWND.
2. Resolve process metadata and safe window title.
3. Observe Windows idle time.
4. Segment only active foreground duration.
5. Persist segment to local SQLite.
6. Resolve project locally from deterministic cached rules.
7. Enqueue synchronization.
8. Upload idempotently when online.

## Time aggregation

There are two separate questions:

### Device/user worked time

Aggregate each user's/device's sessions independently.

### Project effort/person-hours

Sum all valid user/device activity sessions assigned to the project, including overlapping intervals across devices/users.

No server service may collapse overlap across devices.

## Same-device overlaps

Auto foreground capture is inherently single-focus. Accidental overlapping records generated by the single auto-foreground stream on the same device should be prevented as a capture-integrity issue; this must never be generalized into normalization of legitimate multi-source activities.

Manual sessions may overlap auto sessions intentionally, including for the same project. Reports expose both Effort (additive sum) and Elapsed Coverage (union of intervals); they must never silently normalize or delete legitimate time.


## Public-host trust boundaries
- Browser operations panel: Laravel Session Auth + WorkTracker admin authorization + CSRF.
- Windows Agent: per-device Sanctum token, least privilege, exact UUID binding.
- Admin API consumers: separate short-lived admin-scoped tokens.
- Device token compromise must not expose reports or management APIs.
- Production transport is HTTPS-only.
